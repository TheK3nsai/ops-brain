Must cover Linux symlinks *and* Windows hard links, with a test that a live session authenticates from the durable file and leaves it byte-identical. Notes, including a latent second credential store worth re-probing on client upgrades: `docs/investigations/overlay-credential-refresh.md`.

### Public-repo hygiene

- **The string guard scans one surface of three.** It reads the tree; it never reads a commit message or a PR body, and the CI half runs after the push has already published. Bodies and messages have leaked more than once, and an edit is cosmetic (the host retains prior revisions). Cheapest real fix: run the guard over `COMMIT_EDITMSG` locally and over any body text before `gh pr create` / `gh pr edit`. Also: an unmergeable PR runs no `pull_request` workflow, so it is unscanned until rebased.
- **Pre-scrub residue is reachable, and a GC request is the wrong lever** — the same class of string is permanently in merged history, which GC never touches. Operator's call between accepting the exposure fleet-wide or planning a history rewrite; don't file the GC request as a standalone. (The related migration waiver is decided: `ROADMAP.md`.)
